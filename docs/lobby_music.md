# 大厅 / 菜单音乐汉化：可行性评估

> 结论先行：**技术上可行，但工作量和风险都远大于配音，不建议放进 v1.0。** 想做的话，建议作为独立的 v2 小项目，只先做一首（原版主菜单曲），先打通"解码 → 替换 → 回写"这条链路，再决定要不要继续。

## 1. 音乐放在哪里（已在两个游戏里核实）

| | 原版红警3 | 起义时刻 |
|---|---|---|
| 所在数据包 | `Data\StaticStream.big` | `Data\StaticStream.big` |
| 音乐数据 | `PathMusicTrack:Track`，源文件名 `ra3music\pc\track.mus`，**242 MB** | 同名资源，源文件名 `ra3epmus\pc\track.mus`，**364 MB** |
| 索引表 | `PathMusicMap:PC_RA3PathMusicMap`（文件头 `PFDx`，EA PathFinder 格式） | `PathMusicMap:PC_RA3EPPathMusicMap` |
| 小缓存 | `PathMusicTrack:Track_Mem`，约 1 MB | 约 1.3 MB |
| 音频段数 | 715 段，共约 201 分钟，其中 ≥60 秒的完整曲目 61 首，<5 秒的过渡片段 415 段 | 1491 段，共约 300 分钟，完整曲目 78 首，过渡片段 1061 段 |
| 编码 | **EA 编码 5 = EALayer3**（EA 改造的 MP3），44.1 kHz 立体声（另有 2 段 48 kHz） | 同左 |

`track.mus` 开头有一张 16 字节一条的"音轨目录"，记录每段的编码和长度，后面才是音频数据；`PathMusicMap` 按偏移量指向这些段。

**大厅播放的是哪首**（来自 `GlobalStream.big` 里的 `PathMusicEvent`）：
- 原版：`PathMusicEvent:MenuTrack`（菜单和大厅共用）。
- 起义时刻：`MenuTrack`，外加 6 首随主菜单人物切换的曲子：`MenuTrackEP1_Cryo / _Natasha / _Ronin / _Tanya / _Tesla / _Yuriko`。

## 2. 哪些曲子有人声

- **原版主菜单曲**：普遍认为是《苏维埃进行曲》（Soviet March，James Hannigan 作曲，俄语合唱 + 独唱）。这是唯一一首我比较有把握有完整歌词的。
- 起义时刻的 6 首人物主题、以及其他 70 多首曲目里有没有人声：**未验证**。要先把 EALayer3 解码出来，用 Whisper 或人声分离扫一遍才能确定。目前项目里没有 EALayer3 解码器，按约束没有下载新工具。

## 3. 汉化要做的事

1. **解码**：把目标曲目从 `track.mus` 里解出来。开源的 vgmstream 支持 EA MPF/MUS 和 EALayer3 解码，需要下载（约 10 MB）。
2. **人声分离**：把伴奏和人声分开，可用 Demucs / UVR 一类模型（约 0.3~1 GB 权重）。
3. **中文歌词**：按原曲旋律和音节数填词，要能唱、要押韵、气势不能丢。只能人工精修，AI 只能出草稿。
4. **中文演唱合成**：IndexTTS2 是说话模型，**唱不了歌**。需要歌声合成或歌声转换模型：
   - 路线 A：歌声合成（DiffSinger / SoulX-Singer 一类），要逐字标注音高和时值的乐谱（MIDI），合唱声部要分别做。权重约 1~3 GB。
   - 路线 B：歌声转换（RVC / so-vits-svc 一类），需要先有人用中文把歌唱一遍做"导唱"，再转换成原版的音色。权重约 0.5~1 GB，但离不开真人导唱。
   - 原曲是**大合唱**，AI 合成合唱比独唱难得多，通常要叠很多轨、做声部区分，否则听起来很假。
5. **混音**：中文人声和原伴奏重新混合，响度和混响要贴近原版。
6. **回写**（风险最高的一步）：
   - EALayer3 **没有开源编码器**。要么自己实现编码（把 MP3 帧重新包装成 EA 的格式，难度高），要么验证游戏能否接受同一张目录里混用其他编码（如语音用的 XAS 或 PCM），这一点**完全未验证**。
   - 新音频长度如果变了，要同步改 `track.mus` 里的音轨目录和 `PathMusicMap` 里的偏移量。PathMusicMap 的结构只有部分公开资料。
   - 这些资源在 `StaticStream.big` 的 static 流里，要用和语音 MOD 一样的覆盖办法另做一个包，多加一个 SkuDef 条目。

## 4. 工作量与风险

| 项目 | 估计 |
|---|---|
| 新下载 | 解码器约 10 MB + 分离模型约 1 GB + 歌声模型 1~3 GB |
| 只做原版主菜单这一首 | 打通链路 2~4 天（主要难在 EALayer3 回写和 PathMusicMap 偏移），填词和合唱合成另算 2~5 天 |
| 起义时刻 6 首人物主题 | 先要确认有没有人声；有的话每首再加 1~3 天 |
| 主要风险 | ① EALayer3 回写可能做不出来，或游戏不认 → 整条路走不通；② AI 合唱质量很可能明显不如原版，容易"出戏"；③ 歌曲版权比台词更敏感（作曲和歌词都受保护），社区发布被投诉的概率更高 |

## 5. 建议

- **v1.0 不做**，先把配音 MOD 发出去。
- 如果要做，第一步只做技术验证：下载 vgmstream，把原版 `MenuTrack` 解出来听一下，再试着把一段**原样重新编码**写回去，确认游戏能播放。这一步通了，再考虑歌词和演唱。
- 更省事的替代方案：不改歌，只给菜单配一段中文的"开场旁白"之类的新内容。这类内容版权风险小，也不用碰 EALayer3 回写。
